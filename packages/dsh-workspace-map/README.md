# dsh-workspace-map

主区域里的**工作区地图**：点最左边那一列图标最上面那个（树形分叉的字形），主区域列出这张只读快照 —— 每个目录放什么、多少文件、多大、在用还是封存。

## 在哪

- **侧边栏**：`sidebar.panellist`，`order: -1`（排最前）。字形由本插件自己画，`currentColor` 描边，跟随主题与选中态。
- **主区域**：`main`（keyed 槽位），`key: workspace-map`。
- 设置页里不再有它（早期版本占过 `settings.section`，已移除）。

## 长什么样

标题一行（含生成时间）+ 三个数字（目录 / 文件 / 体积）+ 按舱位分区 + 每个目录一张卡：

- 只读：这张图不提供跳转、不提供操作，看的是"目录里有什么"。
- 状态只在终态说话：竣工/封存的卡片带一个细徽章（封存是虚线边），在用不标注。
- 所有颜色、边框、字号都走宿主主题 token（`--dsw-alias-*`），深浅色都跟着走。
- 卡片是 `auto-fill` 网格，窄屏自动单列；`竣工`/`封存` 这种分组目录整行铺开，子目录用虚线分隔。

## 数据从哪来

```
构建期            运行期
build-map.mjs  →  client.js  ←  index.js（Host 半侧，每次启动调一次 buildMap()）
```

- `build-map.mjs` 只负责**扫 + 算 + 拼**：目录、一句话说明（`NOTES`）、状态（`STATE_DIRS`）、文件数、体积、顶部统计。
- `ui.template.js` 是**界面模板**，被整段拼进 `client.js`；改长相只改它，改数据只改 `build-map.mjs`。
- `client.js` 是**生成产物**，别手改。

```powershell
cd "工程坞\01-DSH插件\dsh-workspace-map"
node build-map.mjs         # 重新扫目录，重写 client.js
node test/render.test.mjs  # 自检：槽位 / 文案 / 顺序 / 样式 token
```

## 刷新时机

**每次重启自动重扫。** `index.js`（Host 半侧）在 `apply()` 里调 `buildMap()`，启动时重写 `client.js`，所以重启一次就是最新的一张图：

```
[workspace-map] 开机重建地图：21 条目，生成于 2026-10-23 21:01；工程坞顺序 01-DSH插件 → … → 封存
```

不想重启也要立刻刷新：跑一次 `node build-map.mjs` 然后刷新页面。

Client 模块不热加载：**改了插件代码（不只是数据）要重启 DSH**。

## 排序逻辑

`build-map.mjs` 里 `sortKey()` 一条规则管到底：

1. **状态优先**：在用 → 竣工 → 封存（`STATE_ORDER`）
2. **再按数字前缀**：`01` → `02` → …（没编号的排后面）
3. **同号按名字**：`localeCompare('zh')`

所以工程坞的顺序恒是 `01 → 02 → 03 → 04 → 05 → 竣工 → 封存`，不会因为中文排序或文件系统返回顺序而变。

## 加新目录

1. 在 `build-map.mjs` 的 `NOTES` 里补一句它是干什么的（不补就是空说明，卡片不会塌）。
2. 放进 `工程坞` / `成品舱` / `其它` 之一：改 `ZONES` / `OTHER`。
3. 想让它算"终态"（像竣工/封存那样列子目录），在 `STATE_DIRS` 里加一行。
4. 重跑 `node build-map.mjs`，或者干脆重启 DSH。

## 安装 / 卸载

```powershell
dsh plugin --profile web add "D:\DSH Desktop\Harness work\工程坞\01-DSH插件\dsh-workspace-map"
dsh plugin --profile web remove @local/dsh-workspace-map
```

## 局限

- 数据是构建时快照，不是实时：目录变了要重跑 `build-map.mjs` 或重启。
- 文案直接写中文，没走 Client 的 locale 服务（单人工况，多语言是浪费）。
- 不能点击跳转：`main` 槽位给的是内容区，加跳转要宿主的目录路由 API，收益不抵风险。
