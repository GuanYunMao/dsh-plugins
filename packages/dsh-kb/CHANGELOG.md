# Changelog

## 0.12.0 — 2026-10-18

**检索回执**：上下文被压缩后，AI 仍然知道自己查过什么。

- 每次 `kb_search`（AI）或面板检索成功后，记录一条回执：`查了什么 → 命中哪个文件 · 哪一节（分数）`，
  最多保留 5 条，每条最多 3 个命中，**不存正文**。
- 回执随窗口记忆一起渲染进 `<recent-searches>` 区块，挂在 `kb:session-memory` 段里——
  该段每轮都会重新装配，所以**对话被压缩也不会丢**。
- 上限受 `memory.maxReceipts`（默认 5）与 `memory.maxReceiptChars`（默认 700）约束；
  `settings.receipts` 可整体关闭（面板/接口都能改）。
- 回执里的 query 同样做闭合标签拆解，不能拿来伪造注入区块。
- 面板视图 `window.receipts` 暴露最近 5 条，方便确认 AI 手上还有哪几条线索。
- 面板检索现在会带上 `sessionId`，否则没法记到对应窗口名下。
- 配置：`memory.receipts / maxReceipts / maxReceiptChars` 写进 `cordis.patch.yml`。
- 单测 10 → 11：回执注入、上限淘汰、关闭后不注入。

## 0.11.0 — 2026-10-18

检索分数改成 **A + B 结合**：低于硬底线视为"没找到"，中间档保留但标"低置信"。

### 阈值（`search.minScore` / `search.lowScore`，默认 0.25 / 0.5）

实测分布（11 条查询）：无关 0.17~0.20 · 弱相关 0.35~0.39 · 真命中 0.56~0.79。

| 情形 | 行为 |
|---|---|
| 最高分 < `minScore` | 返回空结果 + `matched:false` + `note`（面板显示"没有找到相关内容"） |
| `minScore` ≤ 分数 < `lowScore` | 保留，标 `confidence:"low"` |
| 分数 ≥ `lowScore` | 保留，`confidence:"high"` |
| 全部命中都是 low | 额外给 `lowConfidence:true` |

### 各处表现

- 面板：低置信命中带「低置信」徽标；空结果直接显示接口给的 `note`（不再只写"没有命中"）。
- `kb_search` 工具：结果里逐条标「（低置信）」；全低时开头写"相关度偏低，仅供参考，不要当作确定事实"；
  完全没命中时告诉模型"没有找到相关内容（最高相关度 X）"，避免它拿无关内容硬编。
- `/kb` 命令：同样带"相关度偏低"抬头与逐条标记。
- 面板响应新增 `maxScore / matched / lowConfidence / dropped / thresholds`，旧的 `results` 结构不变。
- 纯函数 `classifySearchHits(hits, {minScore, lowScore})` 导出，单测覆盖四种情形。

## 0.10.1 — 2026-10-18

审计遗留项收尾。

### 当前会话识别（原来的 high）

以前只认侧栏选中行：侧栏收成 rail 时会话行不渲染，记忆页就退化成"先打开一个窗口"。
现在按四层取，**不再依赖侧栏**：

1. 会话区的 `data-conversation-session` 属性（正在显示的那个会话，最可靠）；
2. `localStorage["dsh.sessions.current"]`（`{"sessionId":"…"}`，宿主持久化）；
3. 侧栏选中行 `data-row-key`；
4. `sessions.list` 快照里唯一会话。

实测：完全不点侧栏，面板的 `window.id` 就是 `session-a364d6d8-…`。

### 可访问性

- 面板 `role="dialog" aria-label="知识阁"`；页签 `role="tab"` + `aria-selected`。
- 文件行 `tabIndex=0`，Enter/Space 打开。
- 错误 `role="alert"`、提示 `role="status" aria-live="polite"`。

### 记忆健壮性

- `readText` 区分 `ENOENT` 与其它读取错误：读不了时 `update` **中止写入**，
  不再把它当"没有旧内容"跳过备份直接覆盖。

### 测试（7 → 9 项）

- 新增"`recall` 完全无命中时返回空结果，不拿无关小节凑数"。
- 新增"分块不产生纯尾巴重复块 + `overlapChars ≥ targetChars` 不死循环"。

## 0.10.0 — 2026-10-18

三个独立审计（宿主 / 记忆子系统 / 客户端）+ 运行态攻击矩阵后的一次加固。共 47 条发现，
本版修掉其中**安全、数据损坏、崩溃**类，共 30 余处。

### 安全（这两个是真漏洞）

- **路径穿越**：`/kb/api/library/{rename,delete}`、`/kb/api/rebuild`、`/kb/api/file/open` 的库名参数
  只做了 `trim()` 就拼进 `join(kbRoot(), name)`，`..` 归一化后可对宿主机任意目录**移动/删除/打开/上传**。
  现在统一走 `resolveLibraryName()`：必须是 `kb/` 下真实存在的单层目录；`to` 另走 `validateLibraryName()`
  （含 `/ \ : * ? " < > |`、以点开头、Windows 保留名、>64 字一律拒绝，**不再静默清洗**）。
  > 顺带说明：加固前我用 `{"to":"../逃逸"}` 打了一次，它被洗成 `_逃逸` 并真给库改了名，已恢复。
- **写接口无同源校验**：任何网页都能对 `/kb/api/*` 发简单 POST 触发全库重建/记忆重写。
  现在非 GET 请求校验 `sec-fetch-site` / `Origin` 与 `Host`，跨站直接 403；请求体非法 JSON 返回 400
  （以前降级成 `{}`，会让 `/rebuild` 变成"全库重建"、`/paths` 变成"清空配置"）。
- `/kb/api/paths`：只有真正提供了 `source`/`index` 才更新（之前缺字段等于清空）；索引目录不能是盘根/系统目录。
- 工作区库**禁止删除**（以前只按硬编码名保护，会话未挂载时保护失效——我的测试因此真的删掉了 `Harness work`，
  已从回收站完整恢复并补了"窗口/ 存在即视为工作区库"的兜底）。

### 数据损坏 / 崩溃

- `memory.js` 用了未导入的 `rm`：改名后删除旧文件的清理分支 100% 抛 `ReferenceError` 并被空 catch 吞掉，
  旧文件残留会让陈旧内容"复活"。已补导入。
- 记忆状态 `memory.json` / 索引 / `libraries.json` 全部改成 **tmp→rename 原子写**并串行化；
  状态文件解析失败时隔离成 `memory.json.corrupt-<ts>` 再重建（以前会把空状态写回，元数据全丢）。
- 模型输出被 `maxTokens` 截断时**不再覆盖正文**（以前会把半截记忆写进去，尾部章节丢失）。
- 备份轮换/版本列举改用真正写入的 `namedPath`（以前改名那次更新的旧内容进的是旧路径备份）。
- 更新失败也记 `lastFailedAt` 并受冷却约束（以前路由坏掉时每个 turn/end 都重试一次 60s 调用）。
- 库目录暂时不存在时不再删除项目记录（改标记 `missing`），删除只走显式 `forgetLibrary`。
- `pushChunk` 步长至少 1 + 启动时夹紧 `chunking`（`overlapChars ≥ targetChars` 会死循环到宿主 OOM）。

### 注入

- 两条 `systemPrompt.section` 补 `interpolate:false`：记忆正文里出现 `{{…}}` 时，模板引擎会抛错
  并让**整轮对话**失败。
- 注入正文里 `<session-memory>` 闭合序列做拆解，防止记忆内容伪造区块边界（长期驻留的注入面）。

### 索引正确性

- 索引记录 `fingerprint`（模型/维度/分块）；配置一变就整库重建（以前新旧向量混在一个索引里互相丢分）。
- embedding 响应校验条数、维度、`text_index`（缺一条就会把 `undefined` 向量写盘）。
- `needsRebuild` 双向比对（删一篇加一篇不再漏检）；索引缓存带 mtime/size + 版本校验（外部替换不再读旧副本）。
- 重建进度条目所有失败路径都会清理。

### 接口契约

- `/kb/api/memory/{reveal,update,rollback}` 透传 `library`：库行「打开目录」以前**百分之百失败**。
- `kb_search` 的 `library` 参数同样校验；空 query、未知库名改为明确报错而不是"没搜到"。
- 全库检索时 query 只向量化一次（按模型/维度分组缓存），以前是每库各请求一次。

### 客户端

- 请求带超时（120s）：以前一次挂起就会永久禁用按钮、轮询变常驻定时器。
- 搜索竞态守卫（连按回车只认最新响应）；Esc 不再"取消改名 + 关面板"双动作。
- 记忆正文支持围栏代码块（块内不再当 markdown 解析）、表格单元格里的 `\|` 与单破折号分隔行。
- 冷却倒计时按快照时间折算，每秒重绘到归零（以前数字冻结）。
- 「未建库」标签不再多渲染一个字面量 `w`；`typeof sessions?.scope` 空值保护；`dsh-panel-open` 监听在 dispose 时移除。
- 宽屏入口按钮探测失败时回退 inline（以前会永久不可见）。

## 0.4.0 — 2026-10-18

修「面板显示别的窗口（REA）的记忆」，并补上库的重命名 / 删除。

### 会话归属（根因）

- 客户端一直读 `sessions.list.getSnapshot().current` —— **这个 DSH 版本的快照里没有 `current` 字段**
  （真实形状是 `{ ids, byId, phase, projectionsBySession }`），于是永远返回空串；
- 宿主侧于是退回"最近活动的会话"，那份恰好是 REA 窗口 → 面板把 REA 的记忆标成「当前 / 已注入」。
- 修复：
  - 客户端按 `侧边栏选中行(data-row-key) → 快照候选字段 → ids 只有一个时取它` 的顺序取当前会话；
  - 宿主**不再**做"最近会话"兜底：拿不到 id 就是拿不到，面板显示「未识别窗口」；
  - 会话对象没挂载、但 id + 库名已知时，仍按 `<库>/窗口/<短id>.md` 读出那份记忆（标「未挂载」，只读展示）。
